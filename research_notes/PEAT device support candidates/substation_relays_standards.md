# Substation relays, standards-based protocols, and file formats as PEAT module candidates

Scope: IEC 61850 (SCL files + MMS nameplate), COMTRADE, DNP3 device attributes, IEC 60870-5-104, IEEE C37.118, plus vendor relay/gateway/switch ecosystems (ABB/Hitachi Relion + RTU560, GE Multilin, Schneider Easergy/MiCOM/Sepam, Beckwith, Basler, Eaton Form 6, NovaTech Orion, Siemens RUGGEDCOM ROS, extra SEL devices) and hardware-free simulators for CI. Research date: 2026-10-31. Note: the web-search budget for this session ran out mid-task; later items were closed with direct fetches of primary pages, and anything that could not be verified is listed under Gaps rather than asserted.

Maintainer weighting applied throughout (per coordinator): the baseline for a new module is PARSE + SCAN. Each candidate is rated on (1) redistributable sample files for a parser and (2) a free, network-reachable simulator that answers on real TCP/UDP ports so a scan can run in CI without hardware. Pull/push are secondary.

## Key Question 1: Which standards-based formats/protocols give the broadest multi-vendor coverage per unit of effort, and what free simulators exist to test them in CI?

### Takeaway
IEC 61850 SCL parsing (vendor-neutral XML, redistributable samples, permissive Python libs) and COMTRADE parsing (MIT library with 14 bundled fixtures, Python 3.11+) are the two cheapest multi-vendor wins and need no hardware at all; IEC 61850 MMS nameplate discovery and DNP3 Group-0 device-attribute reads are the best multi-vendor *scan* paths, and both have GPL-compatible, headless simulators (libiec61850 server examples / the MIT-or-Apache `iec61850` PyPI server, and opendnp3 outstation examples / Sandia bennu in Docker). IEC 104 and C37.118 are cheap to add but yield little identity data and (for 104) have lower US relevance. One major legal trap: Step Function I/O's `dnp3` license forbids using it to test or validate any other DNP3 implementation, so it must not be used as a CI oracle for a PEAT DNP3 module.

#### DNP3 (IEEE 1815) — device attributes (Group 0) as a scan/fingerprint path
- Group 0 "Device Attributes" variations as encoded in Wireshark's GPL dissector: 242 manufacturer's software version, 243 manufacturer's hardware version, 244 user-assigned owner name, 245 user-assigned location, 246 user-assigned ID code/number, 247 user-assigned device name, 248 device serial number, 249 DNP3 subset and conformance, 250 product name and model, 252 manufacturer's name, 254 "non-specific all-attributes request", 255 "list of attribute variations"; 196–201 cover configuration ID/version/build date/last-change date/signature; 209 is Secure Authentication version — [Wireshark packet-dnp.c](https://gitlab.com/wireshark/wireshark/-/raw/master/epan/dissectors/packet-dnp.c)

### Inferences
- Coverage-per-effort ranking (standards only): (1) SCL parse — one lxml-based parser yields IED name/type/manufacturer/configVersion, per-AccessPoint IP/subnet/gateway, LD/LN inventory, GOOSE/SV control blocks and datasets for ABB, Siemens, GE, SEL, Schneider in one module; effort small (days to ~2 weeks) given the XSDs are redistributable under the IEC CC-EULA and `iec61850`'s `load_scl` already returns a dict. (2) COMTRADE parse — reuse the MIT `comtrade` package (Python >=3.11 matches PEAT) and its 14 fixtures; effort small (days). (3) IEC 61850 MMS nameplate scan — read LLN0.NamPlt / LPHD.PhyNam after MMS Identify; effort medium (2–4 weeks) because the Python options are either GPL wheels without macOS (`pyiec61850-ng`), a Pre-Alpha MIT/Apache package (`iec61850`), or AGPL + Python 3.13 (`py61850`, incompatible with PEAT's 3.11 floor); CI simulator is solved (libiec61850 server in Docker on Linux; `iec61850` IedServer in-process on all three OSes if its wheels cover them). (4) DNP3 Group-0 scan — a minimal pure-Python DNP3 link/transport/application encoder for a single READ of g0v254 (or g0v255 then specific variations) is ~1–2k lines; effort medium (3–6 weeks incl. CRC, fragmentation, unsolicited handling); CI simulator: build opendnp3 3.1.1 `outstation` example (Apache 2.0) or bennu field device (GPLv3) in Docker — Linux only, so Windows/macOS CI would need a pure-Python stub outstation. (5) IEC 104 scan — cheap (STARTDT + interrogation) but the protocol carries no nameplate; identity is limited to "speaks 104 on 2404/ASDU address", so PEAT would gain liveness/fingerprint only; `c104` gives an in-process server on Linux/Windows. (6) C37.118 — pyPMU's TinyPMU gives a TCP simulator; a scan would send a CFG-2 command and parse station name/IDCODE, but pyPMU is alpha and unmaintained since 2017, so PEAT would write its own frame codec (small, ~1 week).
- Parse/scan achievability without hardware (standards): SCL parse YES / scan N/A (file format); MMS nameplate parse N/A / scan YES (simulators exist); COMTRADE parse YES / scan N/A (but pull-over-MMS-file-services or FTP is realistic with libiec61850's `server_example_files`); DNP3 parse N/A / scan YES (Linux Docker simulators); IEC 104 parse N/A / scan YES (c104, lib60870, Conpot); C37.118 parse N/A / scan YES (pyPMU, openPDC output streams).
- Licensing fit: PEAT is GPLv3, so GPLv3 dependencies (libiec61850, pyiec61850-ng, lib60870, c104) and GPL-2.0 Conpot (as an external test container, not linked) are compatible; AGPL py61850 is combinable with GPLv3 under GPLv3 §13 but would make the combined work effectively AGPL for network use — avoid. The Step Function dnp3 license's Section 2.6 (no use as a "test oracle" for another implementation) means it cannot be the CI counterpart for a PEAT-authored DNP3 stack; opendnp3 (Apache 2.0, archived) and bennu (GPLv3) are the safe oracles.
- Because MMS Identify and NamPlt reads are read-only and most 61850 servers allow unauthenticated association, a PEAT 61850 scan can be unauthenticated; DNP3 Group-0 reads are likewise unauthenticated unless Secure Authentication is enforced (the Wireshark list shows SA version as attribute 209, so even SA presence is discoverable).

## Key Question 2: Where are legitimately redistributable sample SCL / COMTRADE / settings files?

### Takeaway
Redistributable fixtures exist for SCL (libiec61850 GPLv3 ICD/CID, OpenSCD Apache-2.0 SCDs, IEC XSDs under the attribution-only CC-EULA; KIT's lab SCDs only under CC BY-NC) and for COMTRADE (14 MIT fixtures in python-comtrade), but no redistributable vendor settings-file samples (ABB XRIO/CSV, GE .urs, Schneider, Beckwith, Basler, Eaton, NovaTech NCD) were found anywhere public.

## Key Question 3: Which vendor relay/gateway tools are free downloads whose settings-file formats are text/XML (vs. binary) with public samples, and what can PEAT realistically scan/parse per vendor?
