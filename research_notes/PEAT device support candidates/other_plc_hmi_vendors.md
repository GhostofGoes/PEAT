# Other PLC/HMI vendors (non-Siemens/Rockwell/Schneider/CODESYS) as PEAT module candidates without hardware

Research date: 2026-10-31. Scope excludes Siemens, Rockwell, Schneider, Beckhoff, WAGO, Phoenix Contact, B&R, CODESYS (covered by other researchers). Baseline target per PEAT maintainer: PARSE + SCAN achievable without hardware (pull/push secondary). Ranking weights: (1) redistributable sample vendor files to build/test a parser; (2) a free, network-reachable simulator answering on real TCP/UDP so a scan/fingerprint can be tested in CI without hardware.

Method note: the shared web-search budget was exhausted partway through; remaining facts come from direct fetches of vendor pages, CISA pages, PyPI JSON, GitHub, and forum threads. Several vendor pages are JavaScript-rendered or login-gated and returned 403/404/503; those appear as gaps rather than guesses. Source-quality flag: `industrialmonitordirect.com` recurs in results and reads as machine-generated/unverified; its claims are labelled unverified throughout.

PEAT context verified locally: existing modules are in `/home/user/PEAT/peat/modules/{camlin,fortinet,ge,idirect,openplc,rockwell,sandia,schneider/{m340,sage},sel,siemens,uefi,windows,woodward}`; EtherNet/IP code is in `/home/user/PEAT/peat/protocols/enip/` (including `vendor_ids.py`). A repo grep found no existing code for any candidate below (Omron/FINS, Mitsubishi/MC, Unitronics/PCOM, AutomationDirect, Keyence, Weintek, Red Lion, Horner, IDEC, Panasonic, Delta, LS Electric) — every candidate is greenfield.

## Key Question 1: Which free simulators actually open network sockets (scan/pull testable) versus only simulating logic inside the IDE?

### Takeaway
Three candidates have evidence of a free/trial simulator that answers on a real TCP/UDP port on the host: AutomationDirect Do-more Designer's simulator (listens on 28784 on all adapters, plus Modbus/TCP), AutomationDirect Productivity Suite's simulator (Modbus/TCP server/client only), and Keyence KV STUDIO's simulator (host-link over TCP 8501, loopback only). Omron CX-Simulator and Mitsubishi GX Simulator3 are reachable only via vendor middleware (FinsGateway / MX Component), not raw protocol sockets. CLICK, Unitronics, Eaton, IDEC and Panasonic have no network-reachable simulator evidence; several HMI tools (Weintek, Red Lion, C-more) simulate panels on the PC but their network exposure during simulation is unconfirmed.

### Cited Findings
- Do-more simulator (DMSim): a long-time community expert ("BobO") states the simulator "just listens on port 28784 (0x7070) and does not specifically bind to an adapter"; Do-more Designer connects at 127.0.0.1 and the PC's primary NIC address also works; a Modbus/TCP test HMI connected to DMSim using the PC's IP, while a Red Lion Crimson Do-more-protocol driver connection to the simulator failed (thread imported from legacy forum, ~2018) — [AutomationDirect Community: connecting an HMI simulator to the Do-more simulator](https://community.automationdirect.com/s/question/0D53u000029KbeuCAC/connecting-an-hmi-simulator-to-the-domore-simulator)
- Unverified third-party guides claim the Do-more simulator's Modbus/TCP server must be enabled in configuration and defaults to port 502; one gives 28784 — [IndustrialMonitorDirect: Do-More Modbus TCP/IP Simulator Configuration Guide](https://industrialmonitordirect.com/blogs/knowledgebase/do-more-modbus-tcpip-simulator-configuration-guide); [IndustrialMonitorDirect: Configuring Do-More Modbus/TCP Server Registers for Python](https://industrialmonitordirect.com/blogs/knowledgebase/configuring-do-more-modbustcp-server-registers-for-python)
- Productivity Suite simulator: simulation mode requires Productivity Suite 3.8.x+ — [AutomationDirect Community: Productivity Suite PLC simulator video released](https://community.automationdirect.com/s/question/0D53u00002PXHFUCA5/productivity-suite-plc-simulator-video-released); a user states "The Productivity Simulator will only support Modbus TCP server/client connections on the external Ethernet port" and a C-more HMI connects by pointing at the PC's IP (tested C-more 6.51, Productivity Suite 3.8.0.14); no staff confirmation in thread — [AutomationDirect Community: HMI and simulator](https://community.automationdirect.com/s/question/0D53u00002RftjpCAB/hmi-and-simulator)

- Weintek EasyBuilder Pro: official Quick Start describes "off-line simulation" (no PLC) and "on-line simulation", using a MODBUS TCP/IP PLC example — [Weintek EasyBuilder Pro Quick Start (mirror)](https://www.rusavtomatika.com/upload_files/documents/weintek/Document/UM0/EasyBuilder-Pro-Quick-Start-UserManual-eng.pdf); chapter 19 configures the HMI as a "MODBUS Server" device over Ethernet with a configurable port, station via LW-9544, address types 0x/1x/3x/4x/5x/6x — [Weintek EBPro User Manual ch.19 (mirror)](https://rusavtomatika.com/upload_files/documents/weintek/EBPro/UserManual/eng/UserManual_separate_chapter/Chapter-19-Configure-HMI-as-MODBUS-Server-UserManual-eng.pdf). Whether that server is active during PC simulation is not stated in the extracted text.
- C-more EA9: built-in "one click" project simulator renders every screen/object on the PC without a panel or PLC; the page does not say whether it talks to PLCs over the PC Ethernet — [AutomationDirect: C-more project simulator](https://automationdirect.com/c-more/ea9/software/project_simulator)
- Red Lion Crimson: a Crimson user notes panel emulation needs a virtual Ethernet port and "an emulated port limits the session to about 15 minutes" — [AutomationDirect Community thread](https://community.automationdirect.com/s/question/0D53u000029KbeuCAC/connecting-an-hmi-simulator-to-the-domore-simulator); unverified posts say the emulator exists in Crimson 3.0 and 3.2 but was absent in 3.1 — [IndustrialMonitorDirect: Crimson 3.1 Emulator Missing Workaround](https://industrialmonitordirect.com/blogs/knowledgebase/crimson-31-emulator-missing-workaround-for-hmi-development)

### Inferences
- Do-more Designer is the best-evidenced CI target: DMSim binds all adapters on 28784 (same port family as AutomationDirect's ECOM/HAP) and also serves Modbus/TCP, so both a vendor-specific fingerprint and a generic Modbus probe could be exercised against localhost on a Windows runner. Silent-install behaviour of the installer is unverified (gap).
- Keyence KV STUDIO simulator is scan-testable on the same host (loopback TCP 8501 host-link), adequate for a CI job on the same Windows runner, but KV STUDIO's cost/trial status is unverified (gap), so "free" is not established.
- Productivity Suite's simulator exposes only Modbus/TCP; PEAT's Modbus code could confirm reachability but could not vendor-fingerprint unless the simulator answers Modbus FC43/14 (unknown).
- Omron/Mitsubishi simulators are not viable for socket-level scan tests without hardware; a Python mock FINS or MC/SLMP server (as pyclickplc does for CLICK Modbus) is the realistic CI fixture, but it tests PEAT against its own protocol understanding, not vendor behaviour.
- Unitronics has no simulator, but PCOM is simple and documented, so a Python mock PCOM/TCP server (port 20256) answering ID/UG/GF is a small-effort CI fixture.

### Gaps
- Do-more/Productivity/C-more/CLICK official software download pages 404'd to the fetcher; official statements on simulator network behaviour, silent-install switches, and EULA text were not retrieved.
- Whether Weintek on-line simulation or the Red Lion emulator open Modbus/Crimson ports on the host NIC is unverified.
- Keyence KV STUDIO pricing/trial status and whether its simulator runs without a paid license: not found (Keyence pages 404/blocked).
- Delta ISPSoft/DIADesigner, LS XG5000/XG-SIM, Panasonic FPWIN Pro, Pro-face GP-Pro EX, Beijer iX, Advantech WebAccess simulator network behaviour: not verified (pages dynamic/403/503).

## Key Question 2: Which protocols are fully publicly documented and have maintained Python libraries with GPLv3-compatible licenses?

### Takeaway
PCOM (Unitronics), MC/SLMP (Mitsubishi) and FINS (Omron) are publicly documented and each has at least one MIT-licensed Python implementation. AutomationDirect's protocols are only partly covered (Modbus register maps public; Do-more/ECOM/KOPS proprietary) but a current MIT package (pyclickplc) handles CLICK over Modbus and includes a CLICK-emulating Modbus server. The most active Omron libraries (aphyt's `fins` and `aphyt`) are GPLv2 — if GPLv2-only, not combinable with PEAT's GPLv3 code; the MIT `finscommand` avoids that issue.

### Cited Findings
- Unitronics PCOM spec (official, "Document Version: 20/9/04"): ASCII and binary formats; TCP needs a 6-byte header (bytes 0-1 transaction ID, byte 2 protocol 101=ASCII/102=binary, byte 3 reserved, bytes 4-5 length); "PLCs of types M90, M91 and Vision 120 do not support the TCP communication protocol"; Vision 230/260/280 need an installed Ethernet port; commands RE/RA/RB/GS/RT/RM (read bits), SA/SB/SS (set bits), RC/SC (RTC), SW/SNL/D/H/J/SF (write ints), RW/RNL/D/H/J/F/GF/GT/GP/GX/GY (read ints), "Read Operands: Command #77", data tables via binary commands #4 and #68 (ASCII cannot access data tables); checksum = sum mod 256 (ASCII) / two's-complement of sum mod 65536 (binary) — [Unitronics PCOM Protocol PDF](https://www.unitronicsplc.com/Download/SoftwareUtilities/Unitronics%20PCOM%20Protocol.pdf)
- `pcom` (PyPI): "A basic PCOM implementation in Python", MIT, v0.11 (2022-04-01), Ethernet only ("Serial communication is not implemented yet"; "reading a datatable structure is not supported"), no GitHub URL in metadata — [PyPI pcom JSON](https://pypi.org/pypi/pcom/json); [PyPI pcom](https://pypi.org/project/pcom/)
- Claroty Team82 PCOM-Tools: "Unitronics Forensic Tools, including a modular PCOM client, as well as PCOM to TCP converter"; serial & TCP, ASCII & binary; opcodes include 0x01 Read Memory, 0x02 Check Password, 0x0C Get PLC Name, 0x10 Find resources, 0x41 Write Memory, 0x42 Reset Upload Password (CVE-2024-38434), 0x4D Read Operand, ASCII ID / UG (UnitID) / GF (Version); procedures to upload project and dump/parse the signature table; files are `.py`; license not shown on page; 1 commit — [GitHub claroty/PCOM-Tools](https://github.com/claroty/PCOM-Tools)
- Praetorian Nerva (Apache-2.0, Go, maintained fork of fingerprintx, 497 commits, 376 stars) ships fingerprint plugins for Modbus, S7comm, EtherNet/IP, PROFINET, BACnet, OPC UA, OMRON FINS, MELSEC-Q, Codesys, Crimson v3 (Red Lion HMI), PCOM (Unitronics), GE SRTP, and more — [GitHub praetorian-inc/nerva](https://github.com/praetorian-inc/nerva); its Unitronics plugin documents PCOM/TCP on port 20256 with a "6-byte TCP header (transaction ID, mode, length) - ASCII mode (0x65) payload with STX/ETX framing" — [pkg.go.dev nerva unitronics plugin](https://pkg.go.dev/github.com/praetorian-inc/nerva@v1.6.1/pkg/plugins/services/unitronics)
- Commercial PCOM drivers (HMS/Anybus "Unitronics PCOM Binary Master Serial/TCP") corroborate openness — [HMS support article](https://support.hms-networks.com/hc/en-us/articles/35559271788946-Unitronics-PCOM-Binary-Master-Serial-TCP-IP-Communication-Drivers)
- Mitsubishi `pymcprotocol`: MIT, v0.3.0 (2021-04-26), Q/L/QnA/iQ-L/iQ-R (A and FX not supported), 3E tested on Q, 4E implemented/untested, 1C-4C unsupported; `read_cputype()`, `remote_run()/remote_stop()` (via E71 module only; direct CPU returns error C059); 106 stars, 91 commits — [PyPI pymcprotocol](https://pypi.org/project/pymcprotocol/); [GitHub senrust/pymcprotocol](https://github.com/senrust/pymcprotocol)
- Mitsubishi `pymelsec`: MIT, v0.2.5 (2022-09-12), same series/frames, read CPU model, remote run/stop/pause/reset, status/clock/loopback; 31 stars, 11 commits — [PyPI pymelsec JSON](https://pypi.org/pypi/pymelsec/json); [GitHub NothinRandom/pymelsec](https://github.com/NothinRandom/pymelsec)
- SLMP is published by the CC-Link Partner Association (CLPA): building compatible products needs "only software development"; CLPA offers "SLMP materials" in its downloads section (membership/cost not stated) — [CLPA: SLMP](https://www.cc-link.org/en/cclink/slmp/index.html)
- Omron `fins` (author Joseph Ryan / aphyt): "GNU General Public License v2 (GPLv2)" classifier, v1.0.5 (2025-08-21), UDP only, expected to work with Ethernet CP/CS/CJ, "tested on an extremely limited amount of hardware" — [PyPI fins](https://pypi.org/project/fins/); [GitHub aphyt/omron_fins](https://github.com/aphyt/omron_fins)
- Omron `aphyt` (NX/NJ over EtherNet/IP, symbolic variable read/write via explicit messaging): GPL-2.0 LICENSE.txt, v0.1.30 (2026-09-09), Python >=3.10, 364 commits, 28 stars — [PyPI aphyt JSON](https://pypi.org/pypi/aphyt/json); [GitHub aphyt/aphytcomm](https://github.com/aphyt/aphytcomm)
- Omron `finscommand` (OkitaSystemDesign): MIT, v0.1.3 (2026-04-23), FINS/UDP, CJ/NJ/NX, read/write/fill/run/stop — [PyPI finscommand JSON](https://pypi.org/pypi/finscommand/json)
- Omron `omronfins` (TaishiUeda): no license declared, v1.0.3 (2022-01-22), NX series — [PyPI omronfins JSON](https://pypi.org/pypi/omronfins/json); `eidorb/fins`: MIT, partial (memory_area_read/write, clock_read/write), TCP, 8 commits — [GitHub eidorb/fins](https://github.com/eidorb/fins); C library `libfins` implements FINS/TCP — [GitHub lammertb/libfins](https://github.com/lammertb/libfins)
- Omron FINS over Ethernet uses UDP port 9600 (third-party blog) — [IndustrialMonitorDirect: Connecting Omron CX-Simulator to External Applications](https://industrialmonitordirect.com/blogs/knowledgebase/connecting-omron-cx-simulator-to-external-applications)
- AutomationDirect CLICK `pyclickplc`: MIT, v0.4.1 (2026-10-14), async Modbus TCP client plus `ClickServer` that "simulates a CLICK PLC over Modbus TCP" for "development and testing without hardware", and nickname CSV / DataView CDV file I/O; 104 commits — [PyPI pyclickplc JSON](https://pypi.org/pypi/pyclickplc/json); [GitHub ssweber/pyclickplc](https://github.com/ssweber/pyclickplc)
- AutomationDirect CLICK PLUS uses proprietary "KOPS"/"KOPR" session protocols (named in CVE-2025-58069 and CVE-2025-55038) — [CISA ICSA-25-266-01](https://www.cisa.gov/news-events/ics-advisories/icsa-25-266-01)
- Host Engineering (associated with Koyo/DL05/DL06/DL205/DL405 and ECOM/EBC/ERM) site is a frameset shell; no SDK or protocol document links visible — [hosteng.com](https://www.hosteng.com/)
- LS Electric protocol manuals are publicly hosted by AutomationDirect: Cnet I/F manual ch.7 "XGT Dedicated Protocol" — [XBL-C21A/C41A manual](https://cdn.automationdirect.com/static/manuals/lselectric/xblcx1ausermanual.pdf); FEnet I/F manual (ch.5 "Protocols of Various Services", ch.6 "Dedicated Service") — [XBL-EMTA manual](https://cdn.automationdirect.com/static/manuals/lselectric/xblemtausermanual.pdf); EtherNet/IP module manual — [XBL-EIPT manual](https://cdn.automationdirect.com/static/manuals/lselectric/xbleiptusermanual.pdf); index — [LS PLC User Manuals](https://cdn.automationdirect.com/static/helpfiles/ls_plc/Content/D_MoreInformation/UserManuals.htm)
- Keyence host-link command/response is documented in the KV-7500/KV-5500 communication manual (third-party upload) — [Scribd: KV Ethernet/host link manual](https://www.scribd.com/document/526710795/key-keth); Keyence EtherNet/IP support doc — [Scribd: KvsEtherNetIP](https://www.scribd.com/document/495951209/KvsEtherNetIP-1)
- Panasonic MEWTOCOL-COM is described (reseller) as Panasonic's proprietary protocol over RS-232/RS-485/Ethernet; no official spec retrieved — [IndustrialMonitorDirect: Finding Panasonic NAIS PLC Programming Software FPWIN](https://industrialmonitordirect.com/blogs/knowledgebase/finding-panasonic-nais-plc-programming-software-fpwin)

### Inferences
- License compatibility: MIT packages (pcom, pymcprotocol, pymelsec, finscommand, eidorb/fins, pyclickplc, KcpX) can be vendored/depended on by GPLv3 PEAT. The GPLv2 classifier on aphyt's `fins`/`aphyt` must be checked for an "or later" clause; GPLv2-only cannot combine with GPLv3 in one program. Nerva (Apache-2.0, Go) is a clean reference to port minimal fingerprint byte-sequences into Python.
- Maintenance: pymcprotocol (2021) and pymelsec (2022) are stale but small and protocol-stable; finscommand (Apr 2026), aphyt (Sep 2026) and pyclickplc (Oct 2026) are actively released. None implement discovery/identity beyond MC "read CPU type" (pymcprotocol/pymelsec), PCOM ID/UG/GF (Claroty), and FINS memory/clock (no FINS Controller Data Read confirmed in any Python lib found).
- PEAT already has Modbus and EtherNet/IP stacks, so Omron NJ/NX (CIP), Keyence KV-7500/8000 (EtherNet/IP), LS XGB (XBL-EIPT) and Productivity/Do-more BRX (Modbus/EtherNet/IP) could be identity-fingerprinted via existing code once vendor IDs are added to `peat/protocols/enip/vendor_ids.py` — but only the Do-more/Productivity Modbus path has a free simulator to test against.

### Gaps
- The Omron W342 FINS commands reference manual and the Mitsubishi SLMP reference manual (SH-080956ENG) could not be fetched (403/404); their public availability is well known but unverified here, and the SLMP "Node Search" discovery command was not confirmed.
- No Python library found for Keyence host-link, LS XGT, Panasonic MEWTOCOL, IDEC maintenance protocol, Horner CsCAN, Do-more native protocol, or Red Lion Crimson link (search budget exhausted before those queries).
- Whether any candidate implements Modbus FC43/14 Read Device Identification was not established.
- Documented UDP discovery broadcasts: only Do-more's 28784 listener and FINS UDP 9600 evidenced; nothing found for others.

## Key Question 3: Which project/config file formats are open (text/XML/zip) and have publicly downloadable sample files usable as parse fixtures?

### Takeaway
Confirmed open container: Unitronics `.vlp` is a ZIP archive (per ZDI). Publicly downloadable sample projects are confirmed for Horner Cscape (industry demo zips incl. water treatment), AutomationDirect C-more (official Sample Projects page), and implied for Do-more Designer/Weintek (examples shipped with installers, not independently verified). Most other formats (.dmd, .adpro, .ckp, .gx3/.gxw, .smc2, .cxp, .eap9, .emtp/.cmtp, .cd3x, .csp, .pjw) are undocumented binaries or unverified, and no vendor's redistribution terms for samples were retrievable.

### Cited Findings
- Unitronics `.vlp`: "The specific flaw exists within parsing of a vlp file, which uses the zip file format" (CVE-2016-4519, VisiLogic OPLC IDE) — [ZDI-16-375](https://zerodayinitiative.com/advisories/ZDI-16-375/); Unitronics help says project files "contain application data in compressed format" and lists clone/project types .dvi, .vdf, .urc, .ura — [Unitronics VisiLogic KB: Creating Project files](https://www.unitronicsplc.com/Download/SoftwareHelp/VisiLogic_Knowledgebase/Utilities/Creating_Project_files_(Clone_files,__.dvi,__.vdf__.urc,__.ura).htm); third-party file-type sites call the format undocumented/closed — [filext VLP](https://filext.com/file-extension/VLP)
- VisiLogic (Vision/Samba) is free: "All Unitronics software & utilities—plus updates—provided at no charge", latest 9.9.01; no simulator mentioned; UniDownloader uses compressed `.udc` files; supported families Vision 120/130/230/350/430/560/570/700/1040/1210 and Samba — [Unitronics: VisiLogic Software](https://www.unitronicsplc.com/software-visilogic-for-programmable-controllers/)
- CLICK PLUS project files contain weakly encoded / plaintext passwords (CVE-2025-67652 CWE-261 "Weak Encoding for Password"; CVE-2025-25051 CWE-256 "Plaintext Storage of a Password"; "An attacker with access to the project file could use exposed credentials to impersonate users, escalate privileges..."), fixed in firmware V3.90; reported by Triskele Labs; not remotely exploitable — [CISA ICSA-26-022-02 (22 Jan 2026)](https://www.cisa.gov/news-events/ics-advisories/icsa-26-022-02)

## Key Question 4: Which vendors matter most for US water/wastewater and small utilities (prevalence, CISA advisories, incidents)?

### Takeaway
Unitronics Vision is the only candidate tied to a confirmed nation-state campaign against US water utilities (AA23-335A: at least 75 devices compromised, at least 34 in the US Water/Wastewater sector). AutomationDirect is widely regarded as ubiquitous in US small/municipal systems (prevalence not independently quantified here) and has recent advisories (CLICK PLUS Sept 2025 and Jan 2026, DirectLOGIC 2022). Among candidates, CISA's vendor facet shows Mitsubishi Electric (44) and Delta Electronics (25) with the most advisories overall, then ABB (13), Fuji (10), AutomationDirect (7), Advantech (5), Yokogawa (4), Horner (2), IDEC (2), Opto 22 (2), LS Electric (1); Omron, Unitronics, Keyence, Weintek, Red Lion, Panasonic and Eaton are not shown as single-vendor facets on the page captured (Unitronics appears via the AA23-335A alert, not a vendor facet).

### Cited Findings
- AA23-335A "IRGC-Affiliated Cyber Actors Exploit PLCs in Multiple Sectors, Including US Water and Wastewater Systems Facilities" (published 1 Dec 2023, last revised 18 Dec 2024): "CyberAv3ngers" (tied to Iran's IRGC) hit Unitronics Vision Series PLCs/HMIs; default communication port 20256 (actors changed it to 20257); devices used the manufacturer default password or none; in ~4 waves Nov 2023-Jan 2024 they "compromised at least 75 devices", "at least 34" in the US WWS sector; actors brute-forced internet-exposed devices on TCP 20256, erased ladder logic, loaded their own, disabled upload/download and defaced the HMI; mitigations include upgrading to VisiLogic 9.9.00, changing the default password and port, and removing devices from the public internet — [CISA AA23-335A](https://www.cisa.gov/news-events/cybersecurity-advisories/aa23-335a)

### Inferences

## Cross-vendor fingerprinting fit with PEAT's existing stack

### Takeaway
PEAT's existing Modbus/TCP and EtherNet/IP (CIP) code is directly reusable for several candidates; FINS, MC/SLMP and PCOM are new but small protocols that fit PEAT's "add a protocol driver" pattern.

### Cited Findings
- PEAT already carries CIP/EtherNet/IP (`peat/protocols/enip/`, incl. `vendor_ids.py`), PCCC, Modbus/UMAS, SNMP, FTP, Telnet, SSH, HTTP, serial, and a PLCopen editor (from task brief; `enip` directory confirmed locally).
- Candidates reachable via CIP Identity once vendor IDs are known: Omron NJ/NX (aphyt uses EtherNet/IP explicit messaging), Keyence KV-7500/KV-8000 (EtherNet/IP support doc exists), LS Electric XGB (XBL-EIPT EtherNet/IP module), AutomationDirect Productivity and Do-more BRX (EtherNet/IP-capable) — see per-vendor EtherNet/IP manuals cited above.
- Candidates reachable via Modbus/TCP (and thus FC43/14 identity if implemented): AutomationDirect CLICK/Do-more/Productivity, Eaton easyE4 (Modbus TCP server on 502 per unverified blog), Weintek HMI-as-Modbus-server, Horner (Modbus TCP server mapping).
- New protocol drivers needed: FINS (UDP 9600), MC/SLMP (TCP/UDP, 3E/4E frames), PCOM (TCP 20256), Keyence host-link (TCP 8501), XGT dedicated (FEnet), MEWTOCOL, IDEC maintenance.

### Inferences
- Lowest-marginal-cost scan additions are vendors PEAT can fingerprint with code it already has (CIP Identity / Modbus Device ID) — but a scan module is only CI-testable where a free simulator answers (Do-more, Productivity via Modbus; Keyence via host-link). Everything else needs a mock server fixture.

### Gaps
- Whether any candidate's EtherNet/IP stack returns a populated CIP Identity object (product name/serial) versus a minimal response was not tested.

## Per-candidate parse/scan verdict and rough effort (PEAT functions achievable without hardware)

Effort: small = days, medium = weeks, large = months. "Parse" and "Scan" stated explicitly per the maintainer's instruction.

- Unitronics Vision/Samba (VisiLogic): PARSE achievable without hardware (free VisiLogic to generate `.vlp` ZIP fixtures; inner encoding must be inspected) — medium. SCAN achievable without hardware (PCOM/TCP 20256 fully documented; mock server from pcom/Claroty/Nerva for CI) — small-medium. Pull of PLC name/UnitID/version via PCOM ID/UG/GF is also small if a mock or device is available. Highest overall priority (incident relevance + open protocol + open file container + reusable code). Legal: check VisiLogic EULA before shipping a `.vlp` parser; do not redistribute vendor samples without permission.
- AutomationDirect Do-more (Do-more Designer): SCAN achievable without hardware and CI-testable (DMSim listens on 28784 all-adapters + Modbus/TCP on localhost) — small-medium for Modbus-based fingerprint; the native Do-more protocol is undocumented (reverse-engineering/EULA risk) so a Do-more-protocol scan is large. PARSE of `.dmd` is large (undocumented binary) unless limited to exported/CSV artifacts — medium. Strong because it is the one free simulator that answers vendor-ish traffic on a NIC.
- AutomationDirect CLICK / CLICK PLUS (CLICK software): PARSE achievable without hardware and high-value (CLICK project files hold recoverable credentials per ICSA-26-022-02; pyclickplc parses nickname CSV + DataView CDV open formats) — medium for `.ckp`, small for CSV/CDV. SCAN achievable without hardware via Modbus/TCP using pyclickplc's `ClickServer` emulator as the CI fixture — small-medium; CLICK PLUS KOPS/KOPR is proprietary (large). No vendor simulator, but the emulator substitutes.
- AutomationDirect Productivity (Productivity Suite): SCAN achievable without hardware and CI-testable via the simulator's Modbus/TCP server (Productivity Suite 3.8+) — small-medium. PARSE of `.adpro` is large (undocumented) — medium-large.
- AutomationDirect C-more (HMI, free software): PARSE achievable without hardware (free software + downloadable sample `.eap9` projects) — medium (format undocumented). SCAN: HMIs are less of a scan target; achievable only if the panel exposes a service — not evidenced — so scan not readily achievable without hardware — n/a to medium.
- Mitsubishi MELSEC (GX Works3/2): SCAN achievable without hardware only via a mock MC/SLMP server (pymcprotocol/pymelsec give the frame logic; GX Simulator3 is not socket-reachable without MX Component) — medium. PARSE of `.gx3`/`.gxw` is large (undocumented binary; GX Works3 is trial-only/login-gated). MC/SLMP protocol itself is well documented (CLPA). - Omron CJ/CS/CP/NJ/NX (CX-One/Sysmac Studio, trials): SCAN achievable without hardware only via a mock FINS (UDP 9600) or CIP server (CX-Simulator needs FinsGateway; Sysmac simulator reportedly no network I/O) — medium; NJ/NX CIP identity could reuse PEAT's enip code (small) but is untestable without hardware/mock. ### Overall shortlist (by the maintainer's two weights: redistributable parse fixtures + free network-reachable simulator)
1. Unitronics Vision — open PCOM protocol + ZIP `.vlp` + free IDE + confirmed US water incident; parse yes, scan yes (via mock PCOM); no vendor simulator but trivial to mock. Legal check on EULA/samples needed.
