## Key Question 1: Which free simulators actually open network sockets (so scan/pull can be tested) versus only simulating logic inside the IDE?

### Takeaway
Only three candidates have evidence of a simulator that answers on a real TCP/UDP port: AutomationDirect Do-more Designer's simulator (listens on 28784 on all adapters and also serves Modbus/TCP), AutomationDirect Productivity Suite's simulator (Modbus/TCP only), and Keyence KV STUDIO's simulator (host-link over TCP 8501, loopback only). Omron CX-Simulator and Mitsubishi GX Simulator3 are reachable only through vendor middleware (FinsGateway / MX Component), not raw protocol sockets. CLICK, Unitronics, Eaton, IDEC and Panasonic have no network-reachable simulator evidence.

### Cited Findings
- Do-more simulator (DMSim): a long-time community expert states the simulator "just listens on port 28784 (0x7070) and does not specifically bind to an adapter"; Do-more Designer connects to it at 127.0.0.1 and the PC's primary NIC address also works; a Modbus/TCP test HMI connected to DMSim using the PC's IP, whereas a Red Lion Crimson driver using the native Do-more protocol failed against the simulator (thread imported from legacy forum) — [AutomationDirect Community: connecting an HMI simulator to the Do-more simulator](https://community.automationdirect.com/s/question/0D53u000029KbeuCAC/connecting-an-hmi-simulator-to-the-domore-simulator)
- Third-party, unverified guides claim the Do-more simulator's Modbus/TCP server must be enabled in configuration and defaults to port 502 — [IndustrialMonitorDirect: Do-More Modbus TCP/IP Simulator Configuration Guide](https://industrialmonitordirect.com/blogs/knowledgebase/do-more-modbus-tcpip-simulator-configuration-guide); [IndustrialMonitorDirect: Configuring Do-More Modbus/TCP Server Registers for Python](https://industrialmonitordirect.com/blogs/knowledgebase/configuring-do-more-modbustcp-server-registers-for-python)
- Productivity Suite simulator requires Productivity Suite 3.8.x or higher — [AutomationDirect Community: Productivity Suite PLC simulator video released](https://community.automationdirect.com/s/question/0D53u00002PXHFUCA5/productivity-suite-plc-simulator-video-released); a user reports "The Productivity Simulator will only support Modbus TCP server/client connections on the external Ethernet port", and a C-more HMI connects by pointing at the PC's IP (tested with C-more 6.51 and Productivity Suite 3.8.0.14); no staff confirmation in the thread — [AutomationDirect Community: HMI and simulator](https://community.automationdirect.com/s/question/0D53u00002RftjpCAB/hmi-and-simulator)
- CLICK: "There is no simulator for the CLICK" (community answer, 7 May 2016; flagged as possibly outdated) — [AutomationDirect Community: simulate CLICK programming without hardware present](https://community.automationdirect.com/s/question/0D53u000029N9SWCA0/simulate-click-programming-without-hardware-present); the current official CLICK software page describes the free, "fully functional" software and mentions no simulator — [AutomationDirect: Free CLICK Software](https://www.automationdirect.com/clickplcs/free-software/free-click-software)
- Keyence KV STUDIO simulator: the MIT-licensed .NET library KcpX connects to the KV STUDIO simulator "over host link (TCP)" on port 8501, "Verified with KV STUDIO Ver.12.41"; the simulator "listens only on 127.0.0.1" (remote access requires `netsh interface portproxy`), supports KV-8000/KV-X500 projects, allows one simulator connection, and does not support monitor commands MBS/MBR/MWS/MWR — [NuGet: KcpX 0.1.0](https://www.nuget.org/packages/KcpX)
- An open-source Keyence host-link emulator exists (nshimaza/keyence-hostlink-emu) — [Cisco DevNet Code Exchange listing](https://developer.cisco.com/codeexchange/github/repo/nshimaza/keyence-hostlink-emu) (language and license not verified)
- Omron CX-Simulator: a 2015 thread quotes the CX-Simulator manual as requiring FinsGateway for an external program to reach the simulated PLC; the poster could not find FinsGateway/SYSMAC Gateway in CX-One, got connection-refused on both localhost and the PC IP, and ended up using a physical CJ2M — [MrPLC: How can I communicate with a simulated PLC using FINS](https://mrplc.com/forums/topic/28351-how-can-i-communicate-with-a-simulated-plc-using-fins/); a 2006 thread quotes the CX-Simulator 1.6 manual: the application "can access CX-Simulator from network, but on the computer running CX-Simulator FinsGateway is needed" — [MrPLC: access CX-Simulator via Ethernet](https://mrplc.com/forums/topic/7702-access-cx-simulator-via-ethernet/)
- Omron Sysmac Studio: a low-reliability third-party blog claims the built-in simulator does not support EtherNet/IP, CIP messaging or network I/O — [IndustrialMonitorDirect: Omron Sysmac Soft PLC: Simulation vs Hardware Options](https://industrialmonitordirect.com/blogs/knowledgebase/omron-sysmac-soft-plc-simulation-vs-hardware-options)
- Mitsubishi GX Simulator3: forum consensus (2019–2020) is that external software reaches GX Simulator3 only through MX Component (option present in MX Component 4.18+); "if you need to communicate with GX Simulator then use MX Component", direct MC/SLMP is for real CPUs; a Citect-to-simulator attempt never succeeded — [MrPLC: communicate between GX Works 3 in simulation mode and Citect via MX Component](https://mrplc.com/forums/topic/35830-communicate-between-gx-works-3-in-simulation-mode-and-citect-via-mx-component/)
- Eaton easySoft: "A non-licensed version of easySoft with extensive functionality is available for download free of charge"; "Circuit diagrams can first be tested in simulation mode"; full functions need license EASYSOFT-SWLIC; easyE4 Modbus TCP client supported from easySoft V7.30 — [Eaton easySoft catalog page](https://www.eaton.com/ca/en-gb/catalog/machinery-controls/easysoft.html); a third-party blog (unverified) says the free demo permits offline simulation only and cannot download to a device — [IndustrialMonitorDirect: Eaton easyE4 Modbus TCP Slave and Webserver Configuration Guide](https://industrialmonitordirect.com/fi/blogs/knowledgebase/eaton-easye4-modbus-tcp-slave-and-webserver-configuration-guide)

- C-more EA9: built-in "one click" simulator shows every screen/object on the PC with no panel or PLC connected; the page does not state whether the simulator communicates over the PC's Ethernet — [AutomationDirect: C-more project simulator](https://automationdirect.com/c-more/ea9/software/project_simulator)
- Red Lion Crimson: in the Do-more thread a Crimson user notes that panel emulation needs a virtual Ethernet port and "an emulated port limits the session to about 15 minutes" — [AutomationDirect Community thread](https://community.automationdirect.com/s/question/0D53u000029KbeuCAC/connecting-an-hmi-simulator-to-the-domore-simulator); third-party posts say the emulator is present in Crimson 3.0 and 3.2 but was absent in 3.1 (unverified) — [IndustrialMonitorDirect: Crimson 3.1 Emulator Missing Workaround](https://industrialmonitordirect.com/blogs/knowledgebase/crimson-31-emulator-missing-workaround-for-hmi-development)

### Inferences
- For a Windows CI runner, Do-more Designer is the best-evidenced scan target: DMSim binds all adapters on 28784 (the same port AutomationDirect's ECOM/HAP family uses) and also serves Modbus/TCP, so a vendor-specific fingerprint and a generic Modbus probe can both be exercised against localhost. Silent-install switches for the Do-more Designer installer were not verified.
- Keyence KV STUDIO's simulator is scan-testable on the same host (loopback TCP 8501 host-link), which suffices for CI running PEAT on the same runner; KV STUDIO's cost/trial status is unverified, so it may not qualify as free.
- Productivity Suite's simulator exposes only Modbus/TCP; PEAT's Modbus code could confirm reachability but not vendor-fingerprint it unless the simulator answers FC43/14 (unknown).
- Omron and Mitsubishi simulators are not viable for socket-level scan tests; a Python mock FINS or MC/SLMP server would be the realistic CI fixture, which tests PEAT against its own protocol understanding rather than vendor behaviour.
- Unitronics has no simulator, but PCOM is simple and fully documented, so a small Python mock PCOM/TCP responder (port 20256) answering the ASCII identification commands is a days-level CI fixture.

### Gaps
- AutomationDirect's product pages for Do-more Designer, Productivity Suite and C-more returned 404 to the fetcher; official statements on simulator network behaviour, silent installation, and EULA text were not retrieved.
- Whether Weintek on-line simulation or the Red Lion emulator open Modbus/Crimson ports on the host NIC was not verified.
- Keyence KV STUDIO pricing/trial status, and whether its simulator runs without a paid license, not found (Keyence pages returned 404/blocked).
- Cscape Operator Simulator network behaviour not verified.
- Delta ISPSoft/DIADesigner, LS XG5000/XG-SIM, Panasonic FPWIN Pro, Pro-face GP-Pro EX, Beijer iX Developer and Advantech WebAccess simulator network behaviour not verified (pages dynamic, 403 or 503).

## Key Question 2: Which protocols are fully publicly documented and have maintained Python libraries with GPLv3-compatible licenses?

### Takeaway
PCOM (Unitronics), MC/SLMP (Mitsubishi) and FINS (Omron) are publicly documented and each has at least one MIT-licensed Python implementation. AutomationDirect's protocols are only partly open (Modbus register maps are public; the native Do-more, ECOM/HAP and CLICK PLUS "KOPS/KOPR" protocols are not publicly specified), though an actively maintained MIT package (pyclickplc) covers CLICK over Modbus and includes a CLICK-emulating Modbus server. The most active Omron libraries (`fins` and `aphyt`) are GPLv2-licensed; if GPLv2-only, they cannot be combined with PEAT's GPLv3 code.

### Cited Findings
- Unitronics PCOM specification (official PDF, "Document Version: 20/9/04"): ASCII and binary message formats; TCP transport adds a 6-byte header (bytes 0–1 transaction ID, byte 2 protocol selector 101=ASCII/102=binary, byte 3 reserved, bytes 4–5 length); "PLCs of types M90, M91 and Vision 120 do not support the TCP communication protocol"; Vision 230/260/280 require an Ethernet port; commands documented include RE/RA/RB/GS/RT/RM (read bits), SA/SB/SS (set bits), RC/SC (real-time clock), SW/SNL/SND/SNH/SNJ/SF (write integers), RW/RNL/RND/RNH/RNJ/RNF/GF/GT/GP/GX/GY (read integers), "Read Operands: Command #77", and data tables via binary commands #4 and #68 (ASCII cannot access data tables); checksums are sum mod 256 (ASCII) and two's complement of sum mod 65536 (binary) — [Unitronics PCOM Protocol PDF](https://www.unitronicsplc.com/Download/SoftwareUtilities/Unitronics%20PCOM%20Protocol.pdf)
- `pcom` (PyPI): "A basic PCOM implementation in Python", MIT, v0.11 released 2022-04-
