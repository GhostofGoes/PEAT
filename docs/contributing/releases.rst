********
Releases
********
Releases are created when the PEAT maintainers determine a release is warranted: to
support an upcoming deployment or exercise, or when enough notable features have
accumulated (for example new device modules) to get them into users' hands.

Versioning
==========
PEAT uses calendar versioning: the tag is ``v<year>.<month>.<day>`` of the release,
``v2026.9.2`` for a release on September 2nd, 2026. Pre-releases append ``-prerelease``.
The Python package version, the executables' metadata, the container labels, and the
documentation all derive from the tag (see "Versioning" in :doc:`code_guidelines`).

Requirements
============
#. The :doc:`changelog </changelog>` is up to date: every change since the last release
   has a news fragment in ``newsfragments/`` (CI enforces this per pull request), and
   ``pdm run towncrier build --draft`` shows what the release notes will say.
#. The maintainers are comfortable with the current state of ``main``.
#. The GitHub Actions pipelines are passing on ``main``.
#. The Sandia-internal GitLab CI pipeline tests are passing: tests on closed-source
   datasets, and tests on the PEAT device rack (live devices).

Release process
===============
Releases are created by the ``Create Release`` GitHub Actions workflow
(``.github/workflows/release.yml``). Do **not** create the release tag manually; the
workflow creates it.

#. Open `Actions > Create Release <https://github.com/sandialabs/PEAT/actions/workflows/release.yml>`__,
   click "Run workflow", and fill in:

   - ``tag_name``: the calendar version prefixed with ``v``, e.g. ``v2026.4.2`` if the
     date is April 2nd, 2026. Append ``-prerelease`` (``v2026.4.2-prerelease``) to mark
     the release as a pre-release.
   - ``target_branch``: the branch to release from (normally ``main``).
   - ``release_title`` (optional).

#. Wait for the workflow to finish. It:

   - Runs the test workflow and the build workflow with the version stamped into the
     artifacts (Linux and Windows executables, Python package, HTML docs, man page,
     Sneakypeat).
   - Builds the changelog from the accumulated news fragments with Towncrier and commits
     the updated ``CHANGELOG.rst`` to the target branch (skipped if the changelog already
     has an entry for the tag).
   - Creates the annotated Git tag.
   - Dispatches the Documentation workflow, which rebuilds the documentation and deploys
     it to `GitHub Pages <https://sandialabs.github.io/PEAT/>`__ with the new version.
   - Creates a **draft** GitHub release with the artifacts attached: the executables, the
     Linux (``.tgz``) and Windows (``.zip``) bundles with example configurations and the
     install script, the Python package, ``peat_docs.zip``, and ``peat.1``.
   - The tag push triggers the Docker workflow, which publishes the container image with
     the version tag and ``latest`` (``pre-`` prefixed for pre-releases).

#. Verify the draft release in `Releases <https://github.com/sandialabs/PEAT/releases>`__:

   - The change list is correct.
   - All expected artifacts are included: Linux executable, Windows executable, Python
     package (sdist and wheel), docs, man page, Sneakypeat, bundles.
   - Download the artifacts and verify they work. They're tested in CI, but it's good to
     be sure, especially ``peat --version`` showing the release version.

#. Publish the release.
#. Share the release with the relevant stakeholders.
#. Congratulations on a successful release!

Changelog
=========
``CHANGELOG.rst`` is generated by `Towncrier <https://towncrier.readthedocs.io/en/stable/>`__
from the fragments in ``newsfragments/``, so it is never edited by hand except for the
"Known Issues" section at the top. Fragment types: ``feature``, ``bugfix``, ``doc``,
``removal``, ``misc`` (not shown in the changelog). See "Update the CHANGELOG" in
:doc:`index` for how to write one, and ``scripts/build_changelog.sh`` for previewing.

Hotfixes
========
For an urgent fix, branch from ``main`` as usual, merge the fix, and run the release
workflow with the day's date. If ``main`` contains changes that shouldn't ship, release
from a branch cut at the last release tag with the fix cherry-picked onto it, using that
branch as ``target_branch``.
